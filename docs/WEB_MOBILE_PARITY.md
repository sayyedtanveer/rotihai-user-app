Dynamic ownership notes:

- Static brand copy is not represented as API data. The web Home subscription promo is static JSX; subscription plans and admin promotional banners are separately API driven.
- AdminPromotionalBanners → promotional_banners → GET /api/promotional-banners → existing mobile Home banner. Fields and CTA kinds are preserved.
- AdminSubscriptions → subscription_plans → GET /api/subscription-plans → Home plan promotion, catalogue and enrollment.
- AdminCustomSubscriptions → PATCH /api/admin/settings/price-per-roti → admin_settings.price_per_roti → GET /api/custom-subscription/price-per-roti. Mobile has no ₹8 fallback.
- AdminWalletSettings writes wallet_settings and referral_rewards together. Public /api/wallet-settings and /api/referral-settings remain the respective authorities.
- AdminCategories/Products/Inventory/Chefs/Offers drive public catalog, stock, fulfillment, sections and availability. No fabricated ratings, ETAs or product images are introduced.
- AdminDeliverySettings, delivery areas, cart thresholds, roti windows, preorder settings and slots are consumed through existing public validation/calculation APIs. Thresholds are not reinterpreted as an order ban.
- AdminPaymentSettings supplies merchant details and convenience fee configuration. No new merchant ID, gateway or trusted payment provider is invented.
